# Raw input files (synthetic)

Generated by `src/eqops/datasets.py` (seed 2026). Rebuild with
`python -m eqops sql --regenerate`. No real market, firm or client data.

| File | Rows | Format quirks |
|---|---|---|
| `crypto_prices.csv` | ~19,900 ticks, BTC/ETH/SOL-USD, 9 Oct 2026 | timestamps in **epoch milliseconds** |
| `crypto_trades.csv` | 1,504 trades, 5 accounts | timestamps as **ISO-8601 UTC text** |
| `fx_trades.csv` | 1,203 bookings, 5–9 Oct 2026 | currency pair is free text (`EUR/USD`, `EURUSD`, `eurusd`, …) |
| `fix_log.txt` | 795 FIX 4.4 messages | `\|` stands in for SOH; CheckSum and BodyLength are real |

## Problems injected on purpose

**crypto_trades.csv**
- 4 duplicate bookings (same `trade_id` twice)
- 4 trades stamped before the first price tick for their symbol
- 3 trades in `DOGE-USD`, which has no price feed
- 3 fat-finger prices about 10% away from the market

**fx_trades.csv**
- invalid pairs: unknown codes (`EUR/USS`, `USDKSH`), `USD/USD`, `XXX/USD`, `EU/USD`, blanks
- repairable formats: lowercase `eurusd`, `gbp/usd`
- negative or zero rates, zero notional
- 3 value dates before the trade date
- 3 duplicate rows

**fix_log.txt**
- orders that never received an acknowledgement
- 3 fills priced through the client's limit
- 2 execution reports resent with the same `ExecID`
- 1 fill for a `ClOrdID` that was never sent (orphan)
- 1 extra fill that overfills an order
- 1 message with a corrupted CheckSum
